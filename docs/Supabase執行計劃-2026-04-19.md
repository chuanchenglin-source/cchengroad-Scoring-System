## 第一階段：規劃（不動程式碼）

### 目標
把現有 Google Sheets 的資料結構，轉換成 Supabase 的資料表設計。

### 步驟

**步驟 1｜盤點現有 Sheets 欄位**
- 主工程師列出所有工作表名稱與欄位
- 釐清哪些是「主資料」（成員名單）、哪些是「流水帳」（每週回報）

**步驟 2｜設計資料表**

建議結構：

```
teams（大隊）
  id, name

squads（小隊）
  id, team_id, name, leader_name

members（隊員）
  id, squad_id, name, role
  role: "member" / "squad_leader" / "team_leader"

reports（每週回報紀錄）
  id, member_id, week, content, submitted_at, reviewed

scores（分數）
  id, member_id, week, base_score, bonus_score, team_bonus, total_score
```

**步驟 3｜確認角色權限**

| 角色 | 可以做什麼 |
|---|---|
| 隊員 | 填寫回報、查看個人歷史 |
| 小隊長 | 同上 + 看小隊分數 |
| 大隊長 | 同上 + 看整隊分數 |
| 審計官 | 審核回報（打勾） |

**負責人**：主工程師主導，Johnson 協助確認需求

## 第二階段：建置資料庫

### 目標
在 Supabase 建好資料表，並匯入現有成員名單。

### 步驟

**步驟 4｜建立 Supabase 專案**
1. 到 supabase.com 註冊（免費）
2. 建立新專案（選最近的區域，建議 Singapore）
3. 記下 `Project URL` 和 `anon public key`

**步驟 5｜建立資料表**
- 在 Supabase 的 Table Editor 用介面建立（不需要寫 SQL）
- 或複製上方 SQL 結構貼入 SQL Editor 執行

**步驟 6｜設定 Row Level Security（資料安全）**
- 隊員只能看自己的資料
- 小隊長能看小隊所有人
- 審計官能修改 reviewed 欄位

**步驟 7｜匯入成員名單**
- 把 Google Sheets 的成員名單匯出成 CSV
- 直接在 Supabase Table Editor 匯入

**負責人**：主工程師執行，Johnson 協助測試

## 第三階段：前端遷移

### 目標
把現有 HTML/JS 的 `google.script.run` 換成 Supabase SDK，部署到 Vercel。

### 步驟

**步驟 8｜建立 Vercel 專案**
1. 到 vercel.com 用 GitHub 帳號登入（免費）
2. 把前端程式碼放進 GitHub repo
3. Vercel 連接 repo，自動部署

**步驟 9｜安裝 Supabase JS SDK**
```html
<!-- 在 HTML head 加入這一行 -->
<script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2"></script>
```

**步驟 10｜替換 API 呼叫**

現在的寫法（Apps Script）：
```javascript
google.script.run.getMemberList();
```

換成（Supabase）：
```javascript
const { data } = await supabase.from('members').select('*');
```

需要替換的函式：

| 原本（Apps Script） | 換成（Supabase） |
|---|---|
| `getMemberList()` | `supabase.from('members').select(...)` |
| `saveForm()` | `supabase.from('reports').insert(...)` |
| `getPersonalHistory()` | `supabase.from('scores').select(...)` |
| `getUserStatus()` | `supabase.from('members').select(...)` |

**步驟 11｜設定環境變數**
- 在 Vercel 設定 `SUPABASE_URL` 和 `SUPABASE_ANON_KEY`
- 程式碼不直接寫入金鑰（安全性）

**負責人**：主工程師執行

## 第四階段：Dashboard 頁面

### 目標
建立各角色的查看頁面，取代 Looker Studio。

### 需要建的頁面

| 頁面 | 對象 | 內容 |
|---|---|---|
| `dashboard-squad.html` | 小隊長 | 小隊每週分數、個人排名 |
| `dashboard-team.html` | 大隊長 | 整隊各小隊分數比較 |
| `dashboard-audit.html` | 審計官 | 待審核清單、打勾功能 |
| `dashboard-rank.html` | 所有人 | 排行榜 |

### 技術

```html
<!-- 加入 Chart.js（免費圖表套件） -->
<script src="https://cdn.jsdelivr.net/npm/chart.js"></script>
```

用長條圖顯示分數、用表格顯示排名，樣式沿用現有 Tailwind CSS。

**負責人**：主工程師建骨架，Johnson 協助用 Claude Code 補內容
