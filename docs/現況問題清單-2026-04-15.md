## 🔴 類別 1：程式 Bug（可以直接修復）

### Bug #1：歷史頁顯示的不是本人的資料（寫死了某個 ID）

**檔案位置**：`webApp.js` 第 168–170 行

**現象**：
任何人打開「查看個人歷史紀錄與分數」頁面，看到的都**不是自己**的資料，而是 `T01_小巴_大心` 這個使用者的資料。如果 `T01_小巴_大心` 在彙總表裡沒有資料，畫面就會一片空白（全是 0）。

**實測驗證**：
- 我用「小花（T01_小花_大心）」的身份打開歷史頁
- 小花在「每日個人分數結算」分頁裡**有一筆 2810 分的資料**（5/07）
- 但歷史頁顯示**全期累計 0 分**
- 原因：程式去查 `T01_小巴_大心` 的資料，小巴剛好沒填過，所以回傳空陣列

**根本原因**：
```javascript
function getPersonalHistory() {           // ← 沒有接收參數
  const SHEET_NAME = '每日個人分數結算';
  let userId = "T01_小巴_大心";            // ← 硬寫死測試用的 ID
  ...
}
```

前端 `history.html` 有把 `campaignConfig.user.id` 傳進這個函式，但函式定義沒有 `userId` 參數，所以傳進來的 ID **被完全忽略**。

**影響**：
- 歷史頁功能**完全失效**，所有人看到的都是同一個人的資料（或空白）
- 以為資料沒存到的人會再填一次 → 重複資料

**修法建議**：
```javascript
function getPersonalHistory(userId) {       // ← 加上參數
  const SHEET_NAME = '每日個人分數結算';
  if (!userId) return [];                   // ← 沒 ID 就回傳空陣列
  ...
}
```

### Bug #6：BOX 7（生生世世系列）分數永遠算不到

**檔案位置**：`main.html` 第 436 行（前端）與第 242–245 行（HTML 結構）

**現象**：
使用者在 BOX 7 勾選「告別負債」或「告別貧窮」後，畫面上方的「今日總得分」**不會增加**，送出後資料庫裡的 BOX 7 分數也是空白或 0。

**實測驗證**：
- 我用小花身份進入填分頁，先勾 BOX 1（陰陽拳 10 分）+ BOX 3（親證心得 30 分）→ 總分正確顯示 40
- 再勾 BOX 7 兩個選項（理論上各 +300，共 +600）→ 總分**還是 40**，沒加上去
- 送出後 Google Sheets 第一大隊分頁的 BOX 7 欄位也是空白

**根本原因**：
前後端的 checkbox 名稱對不上。

HTML 裡兩個 checkbox 的 `name` 都是 `box7`：
```html
<label><input type="checkbox" name="box7" value="300"> 已報名「告別負債」</label>
<label><input type="checkbox" name="box7" value="300"> 已報名「告別貧窮」</label>
```

但 JavaScript 讀取時用的是 `box7_1` 和 `box7_2`：
```javascript
scores.box7_SCORE = (formData.get('box7_1') ? 300 : 0) + (formData.get('box7_2') ? 300 : 0);
```

**讀不到 → 永遠 0 + 0 = 0**

**影響**：
- 有報名生生世世系列的學員拿不到該有的 300 / 600 分
- 總分計算錯誤
- 可能是重大積分誤差來源

**修法建議**（兩種擇一）：

方案 A：修前端 JS 改用 `name="box7"`
```javascript
const b7Count = form.querySelectorAll('input[name="box7"]:checked').length;
scores.box7_SCORE = b7Count * 300;
```

方案 B：修 HTML 把兩個 checkbox 的 name 改成 `box7_1` 和 `box7_2`
```html
<input type="checkbox" name="box7_1" value="300">
<input type="checkbox" name="box7_2" value="300">
```

### 問題 3-1：`TEAM_MAP` 對照表跟實際資料命名不一致

**檔案位置**：`config.js` 第 14–20 行

**現象**：
```javascript
const TEAM_MAP = {
    "T01": "第一大隊",      // ← 程式認為 T01 叫「第一大隊」
    "T02": "第二大隊",
    ...
```

- T01 → `T01_大心`
- T02 → `T02_隨心`

而**試算表分頁**的命名則是「**第一大隊**」、「**第二大隊**」（跟 TEAM_MAP 一致）。

**結果**：
- 使用者畫面上看到的是 `T01_大心`（從人員總表 C 欄來）
- 資料寫入的分頁是 `第一大隊`（從 TEAM_MAP 對應）
- **同一個隊伍有兩個不同的名字**，容易讓主工程師、活動方、系統開發者三方混淆

**建議討論**：
- **統一命名**：決定用「第一大隊」還是「T01_大心」，全部改成一致
- 或在 `TEAM_MAP` 增加說明：「這個是給內部用的分頁名稱，使用者看到的是人員總表 C 欄」

## 🔵 類別 4：安全性考量

### 問題 4-1：網頁存取權是「任何人（匿名）」

**檔案位置**：`appsscript.json`

```json
{
  "webapp": {
    "executeAs": "USER_DEPLOYING",
    "access": "ANYONE_ANONYMOUS"
  }
}
```

**現象**：
- 任何人只要知道 Web App 網址就能打開，**不需要 Google 帳號登入**
- 身份識別只靠使用者在 Index 頁「輸入姓名或編號」

**潛在風險**：
- 可以**偽造身份填分**：某人知道別人的 ID（例如 `T01_小花_大心`），就能用那個人的身份填假分數
- 網址如果外流（LINE 群轉發、截圖等）可能讓陌生人進入系統
- 歷史頁現在因為 Bug #1 全部看同一個人的資料，但修好後，任何人都能看到任何人的歷史

**要問**：
- 這個匿名設計是**刻意的**嗎？（有些活動內部用的系統會刻意不綁 Google 帳號方便使用）
- 如果可以接受，建議至少在送出前加**簡單驗證**（例如生日後四碼或手機尾碼），稍微擋一下誤操作
- 如果要嚴格：改成 `ANYONE`（需要 Google 帳號登入）

## ⚪ 類別 5：設計觀察（不是問題，但要知道）

### 觀察 5-1：歷史頁不會即時反映剛填的分數

**為什麼**：
- 使用者填分後，資料寫入「第一大隊」等**原始分頁**
- 歷史頁讀的是「**每日個人分數結算**」分頁
- 這個分頁由 `schedule.js` 的 `rebuildSummaryReport()` 函式產生，是**排程式**執行
- 除非主工程師有設 Google 觸發器定時跑，否則填分後不會自動彙總

**實測**：我剛填了一筆 40 分的資料，但歷史頁（如果 Bug #1 修好後）也不會立刻看到，要等下次 `rebuildSummaryReport` 執行完。

**建議討論**：
- 確認 `rebuildSummaryReport` **目前有設定排程觸發器嗎**？多久跑一次？
- 需不需要改成**送出時即時彙總**（讓使用者立刻看到）？
- 或在歷史頁加個「最後更新時間」讓使用者知道
